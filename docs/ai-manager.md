# Saltygram AI 管家

## 使用

双击会话列表顶栏的 Saltygram 项目名进入管家会话（触摸端双击也可）。未配置时显示功能欢迎页和设置入口；已连接时恢复聊天及按文字消息区间聚合的工作流胶囊（展开显示每步工具、参数、返回摘要和耗时）。设置 → AI 管家，或会话页右上角的设置按钮，可进入独立配置页。默认后端地址已随前端发布。后端访问密钥在本机 `.data/AI-连接信息.txt`；所有设备使用相同地址、相同密钥并登录同一 Telegram 账号，即共享角色、记忆、对话和当前任务。

管家会先回复文字再执行工具，普通问候直接回复；操作完成后再汇报结果。

在「角色与 API 设置」填写公开 HTTPS API 地址（通常以 `/v1` 结尾）和 API Key，点击「读取模型」，选择支持工具调用的模型并保存。接口兼容 `GET /models` 与 `POST /chat/completions`；不支持模型列表的服务可以手填模型 ID。不同服务商的专有接口不在第一版范围内。AI 推理费用取决于你填写的服务商，与 Cloudflare 免费托管不是一回事。

可以读取会话资料、分页消息、搜索消息、话题和分组；创建或调整分组、排序分组、调整置顶；保存长期偏好。工具返回的消息有明确截断标记和分页游标。设置中单独开启「账号操作」后，还支持发送/回复、编辑、删除/撤回、转发、已有 Telegram 附件重发、消息置顶、已读、会话归档/静音/删除/清空/退群、拉黑/解黑/举报、建群、成员及管理员管理、群组资料修改。每一步需人工确认，权限由 Telegram 校验。

## 架构和边界

Cloudflare Worker 负责 AI API 请求，SQLite Durable Object 按 Telegram ID 保存配置、任务、聊天记录、长期记忆和操作日志。使用 Workers Free 可用的 SQLite DO，不启用付费套餐或付费资源；免费额度耗尽时可能停止服务，不保证无限容量或可用性。

Telegram 工具由当前已登录的在线浏览器执行。不会上传 Telegram Session。跨设备通过工具租约领取任务，一次只处理一个工具；同一账号只运行一个任务。后台标签页暂停轮询，重新打开或切回后继续；关闭所有设备后不会继续读取 Telegram。模型轮次通过 Durable Object Alarm 调度并保存检查点，不依赖前端发起请求的存活时间。超时、输出截断、段预算或上下文问题会明确中断并提供继续入口；16 轮一段、128 轮总上限，每段累计 96000 usage tokens；输出上限 4096 tokens。模型单轮停止不等于任务完成，工具任务必须显式调用 finish_task，失败工具未解决时不能完成。

写操作领取后失联，不自动重放，任务进入「需要核对执行结果」。分组更新校验读取时的版本，防止覆盖其他客户端的新修改。写入前的分组快照保存在日志，保留在后端；可通过读取执行日志找到 eventId，再请求 rollback_folder_change 恢复当次分组快照，需确认且严格校验当前分组仍等于当次修改结果。回滚不是跨 Telegram RPC 的原子事务，中途失败会停下核对。设置页不提供手动导出按钮。停止任务无法撤回已经发往 Telegram 的操作。

后端访问密钥是个人后端的管理凭据，不是 Telegram 登录认证；Telegram ID 仅分区数据。不要把此密钥分享给其他人。AI Key 用 Worker Secret 中的 AES-GCM 密钥加密后保存，不返回前端。访问密钥只存在使用者本机存储中。AI 为分析而读取的 Telegram 文本会发给你选择的 AI 服务商；Telegram 消息中的指令按不可信数据处理，但模型仍可能判断错误。

## 本地开发

```powershell
npm install
npm run ai:prepare
npm run ai:dev
npm run dev
```

`ai:prepare` 仅在没有本地密钥时生成 `.data/ai-backend-secrets.json`，并写入 `.dev.vars`。本地后端端口 8787。连接时可改为 `http://localhost:8787`。局域网访问需前端和后端同时绑定局域网地址。

## 部署

`wrangler.jsonc` 定义 `saltygram-ai` Worker 和一个 SQLite Durable Object 绑定，不包含秘密。

```powershell
npm run ai:deploy
```

首次部署另需通过 Wrangler Secret 设置 `ADMIN_TOKEN` 与 `VAULT_KEY`（32 字节随机密钥的 Base64）；后续部署保留已有 Secrets。保管好原密钥，替换 VAULT_KEY 会导致已保存 API Key 无法解密。前端 `public/public/ai-backend.json` 只保存公开后端 URL。

现有 GitHub → Pages 自动构建只更新静态前端，后端代码修改仍需单独运行 `ai:deploy`。`.data`、`.dev.vars`、`.wrangler` 均忽略提交。

## 验证

`node --test` 包括 Worker 真实运行时的认证、加密 Key 不回传、账号隔离、模型列表、完整工具调用轮次、多设备租约，以及浏览器工具的分组版本冲突、快照和账号切换检查。没有真实服务商凭据时，模型响应使用测试替身，不声称通过了真实模型分析或真实 Telegram 写操作测试。

配置在连接时恢复，并随前台轮询持续同步。角色、模型、API 地址和权限会更新到设置表单；用户正在编辑的字段不会被轮询覆盖，保存后写回共享后端。API Key 不回传明文，显示后端已配置状态并由所有设备共用。


## 新增读取和事件能力

`search_global` 支持关键词、时间范围和媒体类型组合过滤；`read_history` 支持时间范围及 offsetId 断点。`get_admin_log` 返回账号有权限读取的成员/属性变更日志；这不是 Telegram 的完整审计记录。`preview_folder` 只计算规则影响范围。`get_task_log` 按 afterId/untilId 读取一个固定日志快照，可定位恢复用的 eventId。

「同步在线设备收到的新消息事件」默认关闭。开启后，已连接的在线设备将收到的消息/编辑/删除事件推送后端，按事件键去重，最多保留500条；模型通过 get_updates 按游标读取。离线期间未接收的事件不能据此认定不存在，仍需分页查历史。没有部署云端 Telegram Session。

附件工具仅重发账号可访问的 Telegram 现有附件，不接受任意本机路径或外部 URL。任意文件上传到 AI 的附件选择流程尚未增加。API Key/后端访问密钥不会开放为模型工具参数或结果。


### 多服务商与设置页签

管家设置分为「连接后端」「API / 模型」「角色 / 权限」三个胶囊页签。角色、权限、长期记忆和清理执行记录归入第三页；角色保存无需先填写 API 配置。

API 页支持最多20个服务商，分别保存名称、HTTPS 接口、加密密钥、所选模型和读取到的模型列表。旧单服务商自动显示为默认服务商。读取模型后可搜索、点选和分批展开，也可手填 ID；编辑后保存，再设为当前服务商。切换服务商不清除聊天、记忆和人设。删除当前服务商时切换到剩余首个，全部删除后需要重新配置才能发起任务。

服务商配置按 Telegram 账号在后端同步。密钥不会回传前端；留空保留，但更换接口地址后需要填写新密钥，不能把原接口保存的密钥发给新地址。执行中的任务会阻止配置变更；并发更新冲突返回409，避免覆盖另一设备刚保存的配置。


### 贴纸后续对话的接口兼容

历史中最多携带最近一张贴纸。若模型接口以400拒绝带历史图片的请求，且未明确指向其他参数，会仅移除旧图片重试一次；当次新图片、文字和工具调用保持原样。成功后按服务商、接口和模型记住兼容限制24小时，并记录一条提示。失败仍会中断，不会假装识图成功。服务商的具体错误、参数和请求ID会脱敏后记录；不会展示密钥或图片base64。


默认流式回复：模型请求优先 `stream:true`，通过鉴权 SSE 将文本增量送至聊天气泡；工具参数完整拼接并经过验证后才执行。普通 JSON 响应直接兼容；明确拒绝 stream 参数的接口自动退回非流式，并按服务商/模型记忆 24 小时。断流不会自动重发模型请求或执行半份工具参数，任务保留中断状态及已保存文本，可继续。实时连接关闭不取消后台任务，重新打开可恢复；网络不支持 SSE 时仍保留普通状态同步。实时连接每 25 秒续接，仅打开页面且前台可见时保持，文本草稿最多每 500ms 持久化一次。
