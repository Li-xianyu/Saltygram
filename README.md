# Saltygram 0.4 — 浏览器直连

纯前端 Telegram 客户端。GramJS 通过 WSS 直接连接 Telegram，无业务后端。

## 启动

```powershell
npm.cmd install
npm.cmd run dev
```

打开 http://localhost:3000 。固定使用相同协议、域名和端口，localhost 和 127.0.0.1 的浏览器存储互不通用。

```powershell
npm.cmd run build
npm.cmd run preview
```

`dist/` 是完整静态文件。Node / Vite 只负责开发、构建和静态服务，不转发 Telegram 请求。初始不显示演示消息与媒体。

## 聊天

- 每页 50 条。向上滚动接近顶部自动加载，也可点击「加载更早消息」。按会话/话题分别分页、去重，加载时保持滚动位置。轮询保留已加载的旧历史。
- 日期分隔、群消息发送者、未读分隔线、引用预览。点击引用跳转原消息；原消息不在当前列表时加载其附近历史，并显示「回到最新」。跨会话引用当前仅显示摘要，不直接跳转。
- 消息旁「···」菜单提供回复、复制及权限允许时的编辑/删除。回复与编辑在输入框上方显示上下文，可取消。编辑保留原消息 ID；删除先显示确认对话框，私聊可选仅为自己或同时为对方删除，群/频道依 Telegram 规则处理。权限、时限最终由 Telegram 校验，失败会提示且不在本地伪删除。
- 基于 Telegram 的 readInboxMaxId / readOutboxMaxId 显示阅读状态。已发送单勾，已读双勾；收藏夹显示「已保存」，广播频道不声称观众已读。页面在前台且消息实际进入视口后发送已读确认，话题使用独立的阅读位置。通过 Telegram Updates 实时接收新消息、编辑、删除和阅读状态，后台会话摘要与未读数同时更新。每 30 秒补偿同步，重连、网络恢复与重新显示页面时立即补同步。
- 消息内 URL、回调、复制按钮；普通键盘按钮填入输入框。链接与常见富文本可交互。
- 论坛群话题列表（每页 100，可继续加载），按话题读取、分页、回复和发送。

## 贴纸

- 输入框「我的贴纸」读取账号已安装且未归档的普通贴纸包。
- 点击别人的贴纸打开关联包，可「添加到我的贴纸」；服务端成功后才显示已添加。包数量达到 Telegram 限制时可能由服务端归档旧包，页面提示结果。
- 个人贴纸包中点击贴纸发送到当前聊天；其他包可点「用于当前聊天」进入发送模式。发送支持当前话题与引用回复。
- 自动显示 WebP、TGS/Lottie、WebM 贴纸。尚未实现创建、卸载、归档管理、逐张收藏及完整自定义表情。

## 媒体与缓存

- 用户、群和频道真实头像；没有头像或下载失败才用文字占位。
- 图片自动加载缩略图，点击放大原图，无文件名/格式标签。常见 JPEG/PNG/WebP/GIF/AVIF/BMP 支持取决于浏览器，HEIC/TIFF 暂无转换器。
- 视频自动加载 Telegram 缩略图，居中播放键和时长。点击完整下载后原位播放，无文件名/大小标签。视频与图片在消息更新时复用已有节点。
- 音频、文件下载，单文件上限 100 MiB。暂不支持媒体上传、流式播放。
- 记住设备时，凭据与 Session 明文存于 localStorage；消息与媒体副本存入 IndexedDB，按账号隔离，512 MiB 预算与最近使用淘汰。侧栏缓存入口可查看配额/占用、申请保护或清理。退出登录清理本地缓存。
- 缓存消息先显示再同步。引用跳转产生的历史窗口不会覆盖最新会话的磁盘副本。页面关闭后停止运行。

## 验证和边界

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run build
```

测试覆盖历史游标、分页合并、回复 ID、编辑/删除 API 参数、可见消息已读、消息菜单、个人贴纸列表、添加贴纸包和发送贴纸的模拟交互，以及持久缓存、富文本、媒体类型。自动测试使用隔离的模拟账号数据，不修改真实账号消息。

投票、反应、转发、通话、支付、小游戏、WebApp 等尚未完成。接收使用 GramJS NewMessage / EditedMessage / Raw Updates，通过既有 WSS 长连接推送，无 5 秒等待。补偿同步每 30 秒执行，覆盖会话列表、最新消息与当前可见历史；推送只更新相关话题，不刷新无关聊天的正文。并发同步通过版本号避免覆盖新到消息。Telegram 不保证所有删除都会产生完整事件，因此保留补偿机制。



## 增量列表与分类

会话列表按 ID 复用行与头像节点，只更新变化的字段；排序只移动对应节点，筛选后返回复用原节点。列表滚动位置通过可见会话锚点保持。聊天正文同样按消息 ID 增量协调，未变化的消息及媒体播放器保留节点。测试验证未变化的会话没有 DOM 写入。

列表分类包含「全部、未读、私聊、群组」。「私聊」按 Telegram User 实体识别，仅个人用户，排除机器人和本人的收藏夹。搜索可与分类组合使用。未读数占独立列，长消息预览省略，数字气泡禁止挤压并水平、垂直居中。

## 右上角会话菜单

右上角三点按会话类型显示操作：添加/编辑联系人、媒体与文件、标记未读、复制公开会话链接，以及可用的清空记录、删除私聊、退出群组或退订频道。添加联系人可以不填写手机号，默认不设置分享本人手机号的隐私例外。

清空/删除/退出必须在操作对话框中确认；私聊的「同时为对方删除」默认关闭。群话题视图中的清空作用于整个群组，确认文案明确说明；群记录清空只发送 forEveryone=false，不清理其他成员历史。API 成功后才更新界面、失效对应会话缓存，接口拒绝时保留界面并提示原因。标记未读关闭当前会话，未读分类显示标记点，再次打开会话会清除手动标记。

尚未加入私密对话、自动删除时间、静音等菜单项。

## 圆屏滚动动效性能

保留现有缩放效果，优先 CSS 原生滚动动画，兼容路径仅更新可见及预备区域。运行 `npm run bench:round-list` 查看可重复的 DOM 操作计数；优化约束、前后对比及真机验证范围见 [性能说明](docs/round-list-performance.md)。
